# Architecture and Deployment Guide

## 1. Project Overview
**Password Manager** is an application designed to securely store, manage, and retrieve user credentials. It demonstrates fundamental concepts of security, encryption, and data storage. The application focuses on protecting sensitive information in transit and at rest, avoiding common pitfalls such as storing passwords in plain text.

## 2. Architecture
The application employs a hybrid architecture, serving as both a web application and a Command Line Interface (CLI) tool.

### 2.1. Core Components
- **Core Cryptographic Library (`spm.py`)**: 
  - Handles key derivation, encryption/decryption, Two-Factor Authentication (TOTP), and file I/O operations.
  - Employs lock files (`userData.json.lock`) to maintain data integrity during concurrent accesses.
  - Acts as a standalone interactive CLI application for direct management of passwords.
- **Web API & Frontend (`app.py`, `templates/`, `static/`)**: 
  - A Flask-based web application that provides a graphic user interface for adding, modifying, and viewing credentials.
  - Implements lightweight, in-memory session tracking (`SESSIONS`) mapping user tokens to session objects, and an MFA pending state mechanism (`PENDING_MFA`).
  - Implements RESTful-style endpoints for frontend-backend interaction (e.g., `/api/login`, `/api/add_entry`, `/api/mfa/setup`).
- **Data Storage (`userData.json`)**: 
  - File-based JSON storage acting as the primary database. It stores the encrypted payloads, the initial salt, and MFA secrets. 
- **Verification Scripts (`verify_api.py`, `verify_mfa.py`)**:
  - Utility and integration scripts used to assure the logical correctness of the API endpoints and the multi-factor authentication handlers.

### 2.2. Cryptographic Stack
- **Key Derivation**: Uses Argon2 (`argon2-cffi`) with secure parameters (`time-cost=1`, `memory-cost=2048 MB`, `parallelism=8`) combined with HKDF for expansion.
- **Encryption Algorithm**: AES-GCM (Authenticated Encryption with Associated Data), leveraging `cryptography` primitives to ensure both confidentiality and strict integrity.
- **Deterministic Password Generation**: Utilizes HMAC-SHA256 alongside the master key to create reproducible passwords dynamically without saving them.
- **Multi-Factor Authentication (MFA)**: Built upon Time-Based One-Time Passwords (TOTP) utilizing the `pyotp` framework.

## 4. Setup, Deployment, and Usage Commands

### 4.1. Setup & Installation
Follow these exact steps from your terminal to establish the environment:

1. **Clone the repository:**
   ```bash
   git clone https://github.com/ItsMinni1/Password-manager.git
   cd Password-manager
   ```

2. **Create and activate a virtual environment (Recommended):**
   ```bash
   python3 -m venv venv
   source venv/bin/activate  # On Linux/macOS
   # On Windows use: venv\Scripts\activate
   ```

3. **Install application dependencies:**
   ```bash
   pip install -r requirements.txt
   npm install  # (If resolving specific unbundled frontend packages via package.json)
   ```

### 4.2. Running the Application

The system exposes two primary modes of operation.

**Mode A: Web User Interface**
```bash
python app.py
```
- Starts the local Flask development server. Access the user portal in your browser at: `http://127.0.0.1:5000`

**Mode B: Interactive CLI Tool**
```bash
python spm.py
```
- Direct command-line interaction allowing authentication, vault unlocking, and deterministic credential generation without requiring a browser.

### 4.3. Verification & Testing
Integrity tests verifying the MFA flows and API interactions:
```bash
python verify_mfa.py
python verify_api.py
```

## 5. Deployment Considerations (Limitations)

This project focuses on fundamental security paradigms and is tailored for **learning/academic purposes**. Significant upgrades are required before considering production deployment:
- **Web Server**: `app.run(debug=True)` must be replaced with a production-grade WSGI server like Waitress or Gunicorn.
- **Session/State Management**: In-memory `SESSIONS` limits scalability across multiple server nodes. Requires migrating session state to Redis or a relational DB.
- **Networking/TLS**: A reverse proxy (e.g., Nginx) must manage strict SSL/TLS certificates and HTTPS redirection because `app.py` passes data in local plaintext.
- **Data Persistence**: Scaling up would necessitate abandoning `userData.json` in favor of a robust SQL/NoSQL RDMS instance.
